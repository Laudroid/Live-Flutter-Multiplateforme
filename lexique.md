**Accessibilité** : Ensemble de pratiques (sémantique, lecteurs d'écran) visant à rendre l'application utilisable par tous les profils d'utilisateurs.

**Alignements (Main/CrossAxisAlignment)** : Propriétés permettant de positionner les widgets enfants le long des axes principal et transversal d'un layout.

**Animations** : Techniques de polissage de l'UI, qu'elles soient implicites (AnimatedContainer) ou avancées, pour améliorer l'expérience utilisateur.

**API REST** : Interface de programmation permettant à l'application de communiquer avec un serveur distant via le protocole HTTP.

**Arborescence des widgets** : Structure hiérarchique représentant l'organisation et l'imbrication des composants de l'interface utilisateur.

**Asynchronisme** : Mode d'exécution permettant de réaliser des opérations (ex: appels réseaux) sans bloquer le fil d'exécution principal.

**ChangeNotifier** : Classe utilisée avec Provider pour notifier les composants de l'application d'un changement de données.

**Cloud Firestore** : Service de base de données NoSQL en temps réel proposé par l'écosystème Firebase.

**Dart** : Langage de programmation utilisé par Flutter pour concevoir la logique et l'interface des applications.

**Expanded** : Widget de gestion d'espace permettant à un enfant de remplir l'espace disponible dans une Row ou une Column.

**Firebase** : Plateforme de services backend intégrée à Flutter pour gérer l'authentification et le stockage de données.

**Flutter** : SDK et framework de Google permettant de construire des applications multiplateformes à partir d'un code unique.

**flutter doctor** : Outil de ligne de commande servant à diagnostiquer l'état de l'installation de l'environnement de développement.

**FlutterFire CLI** : Outil de ligne de commande facilitant la configuration des services Firebase dans un projet Flutter.

**Formulaires (Form/TextFormField)** : Widgets dédiés à la saisie de données utilisateur, incluant des mécanismes de validation et de contrôle via GlobalKey.

**FutureBuilder** : Widget spécialisé dans la gestion des états de chargement, de succès ou d'erreur lors d'opels asynchrones.

**Gestion d'état (State Management)** : Mécanismes (setState, Provider) permettant de synchroniser les données de l'application avec l'interface utilisateur.

**JSON** : Format d'échange de données utilisé pour modéliser et parser les informations provenant d'une API.

**Layout** : Organisation spatiale des widgets utilisant des composants de structure comme Row, Column, Stack ou Container.

**Moteur Skia** : Moteur de rendu graphique haute performance utilisé par Flutter pour dessiner l'interface utilisateur.

**Navigation (Navigator 1.0)** : Système gérant le passage entre les différents écrans de l'application et le transfert de données.

**Provider** : Package de gestion d'état et d'injection de dépendances favorisant une architecture scalable.

**Responsive Design** : Conception d'interface s'adaptant à différentes tailles d'écrans via des outils comme MediaQuery ou LayoutBuilder.

**Routes nommées** : Organisation de la navigation utilisant des identifiants textuels pour définir les écrans dans le fichier principal.

**SharedPreferences** : Package permettant la persistance locale de données simples pour gérer les préférences utilisateur.

**Stateful Widget** : Widget dynamique possédant un état interne capable de se reconstruire lors d'une modification de données.

**Stateless Widget** : Widget immuable ne possédant pas d'état interne, dont l'apparence est définie uniquement par ses paramètres initiaux.

**Tests unitaires** : Procédure de vérification permettant de tester isolément la logique d'une partie du code.

**Widget** : Composant fondamental de Flutter servant à construire l'intégralité de l'interface utilisateur.
